# Auditoría del Editor — 2026-08-17

> Verificación del comportamiento real del editor contra su spec (`openspec/specs/editor/spec.md`).
> Objetivo: encontrar la deuda silenciosa - cosas que "funcionan" pero con el contexto equivocado.

## Resumen

El editor cumple **todos** los requirements del spec. No se encontraron bugs funcionales.
Solo hay un hallazgo menor (duplicación de lógica, no afecta el resultado).

## Requirements verificados

### ✅ Requirement 1: El usuario escribe a mano con formato
- **Barra de formato:** B/I/S/U, listas (viñetas/numeradas), H1/H2/H3, enlaces, undo/redo. Verificado en `Editor.tsx` (líneas 539-582).
- **Escritura libre:** el editor permite escribir/copiar/pegar libremente (no todo generado por IA).

### ✅ Requirement 2: El usuario usa herramientas IA sobre el texto
- **Write** (`runAI('write')`, línea 649) - continúa desde el cursor.
- **Describe** (`runAI('describe')`, línea 665) - expande la selección con detalle sensorial.
- **Rewrite** (`runAI('rewrite')`, línea 682) - reescribe con estilo seleccionable (`rewriteStyle` se pasa a `buildRewritePrompt`).
- **Expand** (`runAI('expand')`, línea 714) - expande la escena desde el beat/summary (corto/medio/largo).
- **Dialogue** (`runAI('dialogue')`, línea 756) - genera variantes de diálogo.
- **Tension** (`runAI('tension')`, línea 773) - sube el conflicto del final.
- Todas conectadas a la UI con validación (selección requerida para describe/rewrite/dialogue).

### ✅ Requirement 3: El usuario puede abortar la generación
- **Stop** - `AbortController` + botón "Detener". Ante abort/error, revierte el contenido parcial (`setContent(preStreamHtml)`).

### ✅ Requirement 4: El usuario ve la generación en vivo
- **Streaming** - `ollamaChatStream` (SSE), inserta en vivo. `streamingRef` suprime el autosave durante el stream. El contenido final se guarda explícitamente al terminar.

### ✅ Requirement 5: El trabajo se guarda automáticamente
- **Autosave** con debounce 600ms. Título/resumen on blur.
- **Contador** de palabras y caracteres en el footer.

### ✅ Requirement 6: El editor se sincroniza con cambios externos
- El sync effect depende de `scene?.content` (no solo `scene?.id`), así que aceptar un `rewrite_scene` del co-writer se refleja en el editor sin cambiar de escena.

## Hallazgos

### 🟡 Hallazgo 1 (MENOR): Duplicación de lógica del contador de palabras
El editor contaba palabras inline (`editor.getText().trim().split(/\s+/).filter(Boolean).length`),
mientras que el export usa `countWords()` (función pura en `lib/export.ts`). Eran equivalentes en la
práctica, pero la lógica estaba duplicada.

**Impacto:** bajo. No afecta el resultado. Deuda de mantenimiento menor - si `countWords` cambiara,
el editor y el export divergirían.

**Fix:** ✅ **APLICADO** (commit `9df57e3`). El editor ahora reusa `countWords` de `lib/export.ts`.

## Observaciones (no bugs)

- **Modelo de aceptación:** el editor aplica directamente (solo undo + revert de streaming), a
  diferencia del chat que usa propuesta → diff → aceptar/deshacer. Esto es una distinción de diseño
  intencional, no un bug.

## Conclusión

El editor es sólido. Los 6 requirements del spec se cumplen. El único hallazgo es menor (duplicación
de lógica del contador). No requiere acción urgente.
